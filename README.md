# SCTradeManager

SCTradeManager — локальное веб-приложение для учёта торговых лотов в игре Stalzone. Оно помогает вести покупки и продажи, учитывать накладные расходы и анализировать результат за выбранный период.

## Возможности

- Журнал сделок с покупками, продажами, количеством и датами.
- Фильтрация по названию и датам, переключатель показа непроданных лотов и сортировка таблицы.
- Редактирование полей сделки прямо в таблице; копирование названия по клику и редактирование названия двойным кликом.
- Создание нескольких одинаковых лотов за одну операцию.
- Учёт накладных расходов.
- Учёт закупочных цен четырёх видов мякоти и быстрое добавление мякоти в журнал сделок.
- Финансовая сводка и аналитика прибыли, расходов, оборота и цен сделок.
- Импорт предметов и расходов из Excel.

## Экраны

| Экран | URL | Содержание |
| --- | --- | --- |
| Менеджер сделок | `/items/` | Таблица лотов, добавление и редактирование сделок, фильтр по названию и датам, расходы и мякоть. Корневой URL `/` перенаправляет сюда. |
| Аналитика прибыли | `/items/analytics/` | Фильтр периода, оборот, расходы, резерв, валовая прибыль, график чистой прибыли по дням, сводка по предметам и график закупочной и продажной цены за единицу для выбранного предмета. |

В окне фильтра сделок доступны периоды «Месяц», «Неделя», «3 дня», «Сегодня» и «Всё». По умолчанию выбран диапазон последних 30 дней, включая текущий день.

На экране сделок отображаются расходы, сумма в резерве и чистая прибыль за выбранный период. На экране аналитики дополнительно показаны оборот и валовая прибыль до вычета расходов.

## Как рассчитываются суммы

- Цена покупки и цена продажи — общие суммы лота.
- Прибыль лота равна цене продажи минус цена покупки. Количество не умножает прибыль.
- Продажи и оборот относятся к дате продажи; расходы — к дате расхода.
- Резерв — стоимость непроданных лотов, купленных в выбранном периоде.
- Чистая прибыль равна валовой прибыли за период минус расходы за период.

## Технологии

- Python и Django.
- SQLite.
- Django Templates, обычные JavaScript и CSS без сборщика.
- Bootstrap 5.3.2 и Bootstrap Icons 1.11.3 через CDN.

В репозитории нет `requirements.txt` или `pyproject.toml`. Основные зависимости устанавливаются командами ниже.

## Запуск

### Windows

Запустите `start.bat`. Скрипт создаст виртуальное окружение `venv`, установит Django и `openpyxl`, применит миграции и запустит сервер. Если виртуальное окружение уже есть, скрипт устанавливает зависимости только когда в нём не найден Django.

Либо выполните команды вручную из корня репозитория:

```powershell
py -3 -m venv venv
.\venv\Scripts\python.exe -m pip install django openpyxl
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py runserver
```

### Linux и macOS

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install django openpyxl
python manage.py migrate
python manage.py runserver
```

После запуска откройте <http://127.0.0.1:8000>.

### База данных

Приложение использует SQLite. Путь к базе берётся из `database.path` в корневом `config.json`. Если файла конфигурации нет или он не читается как JSON, используется `db.sqlite3` в корне проекта. Перед миграциями проверьте, что настроен ожидаемый файл базы данных.

Пример структуры конфигурации:

```json
{
  "database": {
    "path": "C:\\Users\\username\\Documents\\SCTradeManager\\db.sqlite3"
  }
}
```

## Импорт из Excel

Команда принимает путь к `.xlsx`:

```bash
python manage.py import_excel path/to/file.xlsx
```

По умолчанию перед импортом удаляются существующие сделки и расходы. Используйте `--dry-run`, чтобы получить отчёт без записи в базу, или `--no-clear`, чтобы добавить данные, не очищая существующие записи:

```bash
python manage.py import_excel path/to/file.xlsx --dry-run
python manage.py import_excel path/to/file.xlsx --no-clear
```

Команда ищет дату покупки в начале названия листа в форматах `ДД.ММ.ГГГГ`, `ДД.ММ.ГГ`, `ГГГГ-ММ-ДД` или `ДД-ММ-ГГГГ`. Данные читает со второй строки: название из столбца B, цену покупки из C, цену продажи из D. Для цены продажи в импортированной записи датой продажи становится дата листа. Количество не импортируется и получает значение по умолчанию — 1. Строку накладных расходов команда ищет по тексту `Накладные расходы:` в столбце A, сумму берёт из столбца E.

## Развёртывание

Проект рассчитан на локальное использование и не включает прикладную авторизацию для экранов и AJAX-операций. Для запуска с `DEBUG=False` задайте `DJANGO_SECRET_KEY` и `DJANGO_ALLOWED_HOSTS`; настройки также включают HTTPS-перенаправление и защищённые cookie. Для production-конфигурации кэш настроен на Redis через `REDIS_URL`.
